**逻辑与**

用 `snez` 检查 `lhs` 是否为 `0`，并用 `sub` 将结果取相反数：此时如果 `lhs` 是 `0`，则结果为 `-1`；否则，结果为 `0`。

由于 `-1` 的二进制表示**为全一**，故此时再用 `and` 将此结果和 `rhs` 进行按位与运算，可以得到二者的逻辑与。

最后再用 `snez` 来判断结果是否非 `0`。

**相等**

用 `xor` 进行异或运算，然后用 `seqz` 判断结果是否为 `0`。

**不等**

用 `xor` 进行异或运算，然后用 `snez` 判断结果是否非 `0`。

**大于等于**

用 `slt` 判断是否小于，然后用 `seqz` 对结果取逻辑非。

**小于等于**

用 `sgt` 判断是否大于，然后用 `seqz` 对结果取逻辑非。

#### 第 3 题

> 为什么框架定义了 `frontend/ast/tree.py:Unary`、`utils/tac/tacop.py:TacUnaryOp`、`utils/riscv.py:RvUnaryOp` 三种不同的一元运算符类型？

因为 AST 上的一元运算符、TAC 中的一元运算符，以及 RISC-V 语句中的一元运算符的定义是不一样的。AST 上的一元运算符对应着的是源程序代码，TAC 中的一元运算符代表三地址码中的一元操作，RISC-V 中的一元运算符表示 RISC-V 中仅含一个操作数的指令。

这些对应着的是不同的“一元运算符”；事实上，它们表示的领域和范围都不同。

### Step 4

#### 第 1 题

> 在 MiniDecaf 中，我们对于短路求值未做要求，但在包括 C 语言的大多数流行的语言中，短路求值都是被支持的。为何这一特性广受欢迎？你认为短路求值这一特性会给程序员带来怎样的好处？

因为短路求值能够可以减少不必要的计算，从而提高程序的运行效率。如果第二个操作数的计算所需时间很长，则短路求值能够跳过这步无用的计算。

而且，在第二个操作数是函数调用的情况下，可能会有副作用（比如说在函数里修改了全局变量）。短路求值可以跳过那些操作，避免这些副作用的发生。

同时，短路求值这一特性可以给程序员带来很多编程下的便利。比如可以直接写：

```c
for (int i = 0; i < n; i++) {
    int index = arr[i];
    if (index >= 0 && brr[index] == '#')
        // ...
}
```

这样对于 `index >= 0` 的短路求值，可以保证 `brr[index]` 这样的访问必定是合法的。
